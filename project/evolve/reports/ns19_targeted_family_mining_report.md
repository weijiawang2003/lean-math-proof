# NS19 — Targeted Family Mining

**Branch:** `ns19-targeted-family-mining`
**Parent:** NS18 (`f925a09`)
**Goal:** grow the two promising NS18 wrapper-only families
(`aesop`-on-Finset and `simp_all`-on-Nat-arith) past the NS20
training gate (≥5 same-family wrapper-only-new wins) without
retraining or modifying the NS9 best genome.
**Outcome:** gate NOT met. Aesop pool grew 3 → 4 unique wins
(below the 5-gate). Simp_all-Nat-arith pool stayed at 2 unique.
NS19 also eliminated the NS18 `-1` Set regression as a side effect
of gating, so the gated variant is strictly better than NS18
aesop_wrapper on preservation sets.

## 1. NS18 recap

NS18 produced 5 truly-new wrapper-only theorems beyond the NS9
wrap baseline across 2 families:

| family | wins | theorems |
|---|---:|---|
| `aesop` (NS18) | 3 | `Finset.coe_insert`, `Finset.cons_eq_insert`, `Finset.disjUnion_singleton` |
| `simp_all` (NS18) | 2 | `Nat.mul_mod_mod`, `Nat.mod_mul_mod` |

Regressions: NS18 `aesop_wrapper` lost `Set.inter_singleton_eq_empty`
on `ns17_set_extra` (-1).

## 2. NS19 design

### 2.1 Wrapper-side change

Extended `StrategyWrapperPolicy` with a backward-compatible field
`theorem_name_tactic_gates: dict[str, list[str]]`:

```json
{"theorem_name_tactic_gates": {"<tactic_substring>": ["<allowed_full_name_prefix>", ...]}}
```

Semantics: when a wrapper-emitted candidate (priority_templates,
family_tactics, fallback, term_builder, retrieved) contains the
substring and `full_name` does not start with an allowed prefix,
the candidate is dropped AND its dedupe-set slot is freed. The
gate explicitly does NOT apply to `ORIGIN_GENERATIVE` (base-model)
output — the routed model already knows when to emit aesop on
Set theorems, and NS9 wrapper's 10/30 Set wins on `ns17_set_extra`
all come via base-model `aesop`. Smoke test at
`scripts/ns19_smoke_test_gates.py` covers both inclusion and
non-filtering of base-model output.

A first-pass implementation was over-broad and filtered base-model
aesop, costing 10/30 Set theorems. The fix (preserve base entries
but discard gated-out priority entries from `seen` so the base
emission survives dedupe) is what the smoke test now asserts.

### 2.2 Experimental variants

Both stored as additive deltas on the NS9 best genome in
`project/evolve/experiments/ns19/`. The NS18 configs and NS9 best
genome are unchanged.

- **`ns19_finset_aesop_only.json`** — exact NS18 `aesop_wrapper`
  config plus `"theorem_name_tactic_gates": {"aesop": ["Finset."]}`.
  Aesop fires only on theorems whose full name starts with
  `Finset.`. Should preserve the NS18 +3 wins on `ns17_finset_extra`
  and eliminate the −1 regression on `ns17_set_extra`.

- **`ns19_nat_simp_arith_targeted.json`** — NS18 `nat_simp_arith`
  plus 6 additional Nat-arithmetic `simp_all` bundles
  (`Nat.add_comm/add_assoc/add_left_comm`,
  `Nat.mul_comm/mul_assoc/mul_left_comm`,
  `Nat.add_mod + Nat.mod_eq_of_lt`,
  `Nat.mul_mod + Nat.mod_mul_left_mod`,
  combined `Nat.add_mod + Nat.mul_mod`, plus `omega`). All new
  tactics gated to `["Nat."]`. Priority budget bumped to 32.

Generated by `scripts/ns19_make_experiment_configs.py`.

### Catalog-exhaustion finding

`project/discovered_theorems.json` has exactly 208 Nat theorems,
all of which appear in the canonical / NS14 / NS16 / NS17 sets.
**There is no unmined Nat surface in the current catalog.** The
NS19 Nat surface is therefore a replay of existing thms under the
new variant rather than fresh ground. Catalog extension from
Mathlib is the only path to growing the Nat-arith pool further;
that is deferred.

## 7. NS20 verdict

**Training NOT justified.** Neither target family reaches the gate
of ≥5 same-family wrapper-only-new wins.

- `aesop` is 1 win short (4 / 5).
- `simp_all` is 3 wins short (2 / 5).

Recommended next arc options (NS20):

1. **Re-mine more Finset surface with the gated aesop variant.**
   80 easy Finset thms produced 1 truly-new win (`Finset.coe_cons`).
   A larger surface (200+ Finset thms, including medium difficulty)
   should plausibly produce 1–2 more. The catalog has 154 unused
   Finset thms total — only ~50% of available Finset surface has
   been touched. **Most promising path.**

2. **Catalog extension for Nat.** Add 50–100 fresh Nat theorems
   from Mathlib (Nat.mod_*, Nat.div_*, Nat.dvd_*, Nat.gcd_*) that
   are not in the current 208-thm catalog. This requires Mathlib
   introspection, not just discovery.

3. **Alternative wrapper tactics for `simp_all`.** Current bundle
   set does not extend the Nat-arith pool. A targeted probe with
   `simp_all [Nat.dvd_iff_mod_eq_zero, ...]` or `omega` chains
   could plausibly find more wins. The `−1` regression on medium
   should be diagnosed first — the new bundles displaced a
   working tactic via budget; lowering `priority_template_budget`
   or appending instead of mixing might recover medium without
   losing the `Nat.mul_mod_mod` win.

4. **Different family entirely.** NS17 audit identified
   `constructor_omega` (16 rows, 14 of which are already in NS9
   wrap on medium) and `split_ifs_omega` as families with denser
   pools than aesop/simp_all but with no new wins beyond NS9.
   Either could become trainable if a complementary wrapper
   capability adds 2–3 wins.

## 8. NS20 dataset recipe (deferred; gate not met)

Once the gate is met, the recipe would be:

- **family**: `aesop` (closer to gate)
- **theorem set**: union of wrapper-only-new theorems —
  `Finset.coe_cons, Finset.coe_insert, Finset.cons_eq_insert, Finset.disjUnion_singleton, <one_more_from_NS20>`
- **training pairs**: harvest `(state_pp, "aesop")` rows from the
  NS19 `ns19_finset_aesop_only_wrapper_*` eval traces.
- **oversample factor**: 10× (per `recommended_oversample_factor`)
- **router**: keep `ns15_router.json` (Finset routes to
  `gen_v5_ns12_balanced`).
- **base checkpoints**: do NOT overwrite. Train a new NS20
  sub-model under `project/models/gen_v5_ns20_finset_aesop/`.
- **negative-control set**: re-evaluate `demo_v1`,
  `nat_defs_medium`, `ns14_set_finset_extra`, `ns17_set_extra`
  post-train. Particular attention to the Set-namespace
  (NS16 curriculum_continue forgetting precedent).

## 9. Side-finding — base-model aesop is a load-bearing capability

The NS9 wrapper baseline solves 10/30 Set theorems on
`ns17_set_extra` via base-model `aesop` emission. This was
unobserved before NS19's broken gate exposed it. The implication
for future wrapper engineering: **any namespace gate that filters
generative model output rather than wrapper-injected output risks
deleting existing capability silently.** The fixed gate semantics
(filter only wrapper-injected entries; preserve dedupe-set hygiene
for base output) is the right default.
